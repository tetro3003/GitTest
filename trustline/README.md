# Trustline — alternative credit scoring for the self-employed

> We turn verified gig and freelance earnings plus work activity into a bank-ready income and risk profile.

Hackathon frontend (phase 1). Borrowers connect income sources and get a **verified monthly income**, a **300–850 score (bands A–E)**, a **recommended max monthly payment** and **plain-language reasons**. Lenders get a dashboard with point-based reasons, a score waterfall, fraud checks, monitoring and API docs.

Everything runs in the browser against a **deterministic mock backend**. Every score is computed by a real TypeScript scoring engine from synthetic transactions; nothing is hard-coded.

The product name, currency (₾ GEL) and all policy thresholds live in [`lib/config.ts`](lib/config.ts).

## Run it

```bash
cd trustline
npm install
npm run dev          # http://localhost:3000
```

| Command | What it does |
|---|---|
| `npm run dev` | Dev server |
| `npm run build` / `npm start` | Production build / serve |
| `npm run lint` | ESLint (Next.js config) |
| `npm run typecheck` | `tsc --noEmit` (strict) |
| `npm test` | Vitest: scoring engine, fraud checks, one test per persona |

Node 20+ recommended.

## Deploy to Vercel

1. Push the repo to GitHub and click **Add New → Project** in Vercel, then import it.
2. Set **Root Directory** to `trustline`. The framework (Next.js) is detected automatically.
3. Optional env var: `NEXT_PUBLIC_API_MODE=mock` (the default).
4. Deploy. No database or secrets are needed for the mock mode.

From the CLI instead: `cd trustline && npx vercel` (then `npx vercel --prod`).

## The scoring engine (`lib/scoring/`)

Pure TypeScript with no React or Next imports, so it can move to the backend as is.

```
ScoringInput (only data from connected sources)
  → income.ts     income series; circular pairs & third-party accounts excluded
  → features.ts   Features (CV, trend, seasonality, FCF, balances, bills, activity…)
  → scorecard.ts  base 500 ± points per factor → ScoreReason[] (one per factor)
  → fraud.ts      5 fraud checks + early warnings
  → index.ts      computeScoreReport(): clamp 300–850, fraud cap, band, decision
```

| Factor | Points |
|---|---|
| Income stability (CV around trend) | +90 … −60 (positive part scaled by history length) |
| Verified income vs segment benchmark | 0 … +60 |
| Trend growing / flat / declining | +30 / 0 / −40 (year-over-year for seasonal earners) |
| Zero-income months (12m) | −15 each |
| Diversification (payers ≥5%) / one payer >80% | up to +30 / −20 |
| Free-cash-flow ratio | 0 … +70 |
| Near-zero balance days | −5 each, cap −40 |
| On-time bills | 0 … +50 |
| Existing loans on time / late | +30 / −50 |
| Gambling share of spending | 0 … −80 |
| Income history length | −40 (<6m) / −15 (<12m) / +10 (24m+) |
| **Activity boost (opt-in)** | 0 … +50, **never negative**. A decline raises an early warning instead |

- **Verified income** is the 6-month *weighted* median of verified inflows. The last 2 months carry half weight (pre-application inflation guard). Self-transfers, suspected circular P2P money and accounts not held by the KYC'd person are excluded. Seasonal earners use the 12-month average.
- **Recommended max payment** = `paymentToFreeCashFlowRatio` (40%) × free cash flow.
- **Bands**: A ≥ 740, B 670–739, C 600–669, D 530–599, E < 530.
- **Fraud checks**: circular money (±15% within 7 days), pre-application spike (> 1.8× prior 6-month median), income vs activity (implied ₾/hour vs segment max), invoices without matching payment, account-holder name mismatch. Any **high** flag caps the score at 599 (band D).

## Mock adapter & switching to the live API

The UI only talks to `api` from [`lib/api/index.ts`](lib/api/index.ts), which implements the `ApiClient` interface in [`lib/api/client.ts`](lib/api/client.ts):

```
getBorrower · startOnboarding · submitKyc · setWorkType · listSources · connectSource ·
disconnectSource · getProfile · listLenders · shareWithLender · listShares · revokeShare ·
getApplicants · getApplicant · getMonitoring · listPersonas (demo) · resetDemo (demo)
```

**Mock mode (default).** [`mock-adapter.ts`](lib/api/mock-adapter.ts) behaves like a server:
- data comes from [`lib/mock/generator.ts`](lib/mock/generator.ts), which uses a seeded PRNG, so the same numbers come out on every run;
- state (connections, shares, KYC) lives in an in-memory DB persisted to `localStorage`;
- every call waits 300–800 ms so loading skeletons are visible and returns a deep copy;
- reports are computed by the real engine, using only the sources currently connected;
- the demo panel's *Simulate API errors* switch makes about 35% of calls fail, to show error states.

**Live mode.**
1. Implement the endpoints sketched in [`live-adapter.ts`](lib/api/live-adapter.ts). The paths mirror the method names, and the request and response types are the ones in `lib/types.ts`.
2. Set `NEXT_PUBLIC_API_MODE=live` and `NEXT_PUBLIC_API_BASE_URL=https://…`.
3. Move `lib/scoring/` server-side (it has no framework dependencies) and add auth headers in `request()`.

No page or component changes are needed.

## Demo personas

| Persona | Story | Engine result |

## 3-minute demo script

1. **Problem (20s).** On `/`, read the pitch line: "Self-employed people earn every day but can't prove it to a bank."
2. **The money shot (40s).** Open `/demo`: five people, one engine, every number computed from transactions. Point out Sandro's activity boost (D → C) and Dato's red flags.
3. **Borrower flow (60s).** Open **Demo** (bottom right), pick **Sandro**, then **Start onboarding**.
   - Continue, add ID and selfie, verify, choose Courier.
   - Connect **Black Sea Bank** and **CityPower & Water** only, then *Build my profile*. The analysis runs and the result is **568 · D**.
   - Go to **Sources**, connect **DeliverGo** (note "Optional — can only improve your score"), then return to **Profile**: **618 · C**, with "Sharing your work activity added +50 points".
   - **Share** with DriveLease: consent screen, then the share code.
4. **Lender view (60s).** In the demo panel switch to **Lender** and open **Dato**.
   - Score capped from 653 to 599. The hatched bars show the excluded "income".
   - Waterfall: the fraud cap step. Fraud panel: expand the circular transfers to show the actual money going back and forth within days.
   - Click the decision settings icon and move the thresholds; the suggestion updates live.
   - *Download report* gives the printable PDF.
5. **Close (20s).** Open **Monitoring**: Tamar's activity is down 35% before her income drops. Then **API**: a bank integrates with one `POST /reports`. Finish with **Reset demo**.

## Design notes

- One brand colour (deep teal) plus semantic green, amber and red; light theme by default, with a dark-mode toggle.
- The categorical chart palette was validated for lightness, chroma, colour-blind separation and contrast in both themes. There are no dual-axis charts: activity vs income is indexed to a common base (average = 100).
- Every chart has an aria label and a **table view** toggle. Numbers use tabular figures. Every data view has loading skeletons, error and empty states.
